# StudyOne 9단계 — Android/iOS의 수동 HTTPS 계정 서버 연결

> Canary 개발 PR. **배포된 계정 서버·실사용 기기 자동 동기화는 여전히 없습니다.** 코드만 추가한 것이며 사용자 공부 기록은 전송하지 않았습니다.

## 무엇을 실제로 추가했나요?

- Android 설정: 사용자가 직접 입력하는 서버 HTTPS URL 및 장치별 Bearer 토큰으로 로컬 v1 / 원격 보안 v2 API 구분.
- iOS 설정: HTTPS 주소 직접 입력과 같은 기능. Debug 빌드는 기존 127.0.0.1:8765 서버도 시험할 수 있음.
- 모든 클라이언트는 기존 로컬 데이터와 서버 상태를 먼저 읽고 새 ID만 후보로 산정.
- 사용자 승인 전 서버에는 기록 데이터가 전송되지 않으며, 승인 후에도 서버와 로컬 상태를 다시 읽어 전송 후보가 바뀌면 중단.
- 인증 토큰을 앱 환경설정, GitHub, JSON 백업 파일에 저장하지 않음.
- Android: 시스템 인증서 체인을 이용한 HTTPS. HTTP cleartext는 Debug의 localhost만 허용하고 Release에서는 시스템 정책으로 차단.
- iOS: URLSession 기본 TLS 인증서 검증, ephemeral 세션 및 HTTP 리다이렉트 거부. Release에서는 HTTP 자체를 코드로 거부.
- HTTPS 원격 주소의 사용자 정보(user:pass), 쿼리·프래그먼트·하위 경로를 거부.
- Android 에뮬레이터 합성 데이터·네트워크 테스트와 iOS Release/Debug 컴파일, 플랫폼별 정적 보안 계약 검사 적용.

## 수동 연결 준비물

운영자가 통제하는 서버에 유효한 HTTPS 인증서가 적용되어야 하며, server/PRIVATE-SYNC-RUNBOOK.md를 따라 계정을 준비하고 기기별 토큰을 발급받아야 합니다. 토큰을 채팅에 보내지 마세요. 사용자 기기에서 별도 승인 버튼을 눌러야만 새 기록이 서버에 보내집니다.

동기화 서버가 배포되기 전에는 URL과 토큰을 입력해도 연결되지 않는 것이 정상입니다. 초기에는 개인 정보가 포함되지 않은 테스트 계정으로 통합 테스트를 진행해야 합니다. 기존 main, 공개 Beta 릴리즈, 사용자 파일은 변경하지 않았습니다.
