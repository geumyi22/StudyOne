# StudyOne 개발 13단계 — iOS 신규 일정·진도 수동 수신 (Canary)

## 구현 범위

- iOS의 HTTPS 계정 서버 연결 UI에서 **신규 일정만 가져오기**와 **신규 진도만 가져오기**를 분리.
- 서버 스냅샷 응답의 스키마/항목수/ID/중복/상태/수정 번호 및 예기치 않은 필드를 엄격히 검증.
- iPhone의 기존 ID는 내용이 같으면 유지, 내용이 다르면 충돌 건수만 표시하며 자동으로 덮어쓰지 않음.
- 신규 항목의 과목·교재·제목을 보여 주고 사용자에게 별도로 가져오기 승인을 요청.
- 승인 전의 로컬 일정·진도 상태와 서버 스냅샷을 승인 직후 다시 비교하며 변동 시 중단.
- 실제 병합 전에 기존 UserDefaults 원본 바이트를 Application Support / StudyOne / BeforeSync 앱 전용 경로에 .bak으로 저장.
- 파일 보호를 설정하여 기기 사용자 데이터 접근을 제한. 서버 계정 토큰, NEIS/OpenAI API 키는 백업에 포함하지 않음.
- 일정/진도별 개별 저장을 이용해 기존 항목 수정·삭제 방지. 전체 자동 양방향 동기화, 상태 자동 업데이트, 삭제 tombstone 적용은 아직 미구현.
- CI에서 iOS Release IPA 빌드와 Debug Simulator 빌드·모바일 보호 계약을 검사.

## 안전 제한

- 실제 HTTPS 호스팅/사용자 계정은 아직 배포하지 않았음. 사용자 실데이터 업로드·마이그레이션 없음.
- iOS 사용자 데이터 가져오기 실기기 검증, 백업 파일의 사용자용 복원 인터페이스, 충돌 해결 및 운영 백업 정책은 이후 추가 필요.
- Android는 별도 PR에서 같은 신규 ID 수신/백업 방식 구현, Windows는 기존 수동 병합 구현.
- 실제 기기 간 **백그라운드 자동 양방향 동기화는 아직 미구현**.
- 현재 ChatGPT 대화가 앱의 사용자 계정과 연결된 것이 아니므로 대화의 `할꺼`와 `변경사항 인지해`는 앱을 직접 수정/조회하지 않음.

기존 GitHub main, 공개 Beta 릴리즈·태그·서명과 사용자 PC/휴대전화 데이터를 그대로 보존하며 Canary Draft만 변경합니다.
