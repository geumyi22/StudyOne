# StudyOne Phase27 — Android/iOS 오프라인 신규 항목 대기열

**개발/Canary 범위.** 실제 사용자 계정·학습 기록, OpenAI API, 공개 운영 서버, 앱 서명과 공식 릴리즈를 변경하지 않습니다. 기존 Windows Phase26과 안전 조건을 맞춘 모바일 수동 동기화 구현입니다.

## 모바일에 추가된 내용

- **Android 개발자 동기화 화면:** 신규 일정·진도를 오프라인에서 앱 내부 JSON에 보관, 상태 조회, 승인 후 첫 요청 수동 HTTPS 재전송, 별도 승인으로 폐기
- **iOS 동기화 실험 화면:** 같은 수동 대기열 기능, HTTPS 계정/권한 확인, iOS Application Support의 파일 보호 속성으로 저장
- **Windows**: 기존 Phase26 로컬 대기열은 변경하지 않음
- 대기열에 서버 주소/계정 UUID와 변경되지 않는 요청 UUID(`requestId`)를 저장. **Bearer 토큰, API 키, 비밀번호는 저장하지 않음**
- 재전송 전에 `GET /v2/session`으로 **동일 계정 + audience=device + scope=read-write + 유효기간**을 확인. 다른 계정·서버·읽기 전용 토큰은 거부
- 1~50개씩 신규 일정·진도만 서버 v2 API로 전송. 기존 서버 ID는 수정·삭제하지 않고 동일 ID 충돌 시 배치 전체를 409로 거부
- 네트워크 오류·서버 응답 유실 이후에도 동일 `requestId`를 사용해 재시도하므로 중복 삽입을 방지
- 오프라인 보관 시점 이후 로컬 원본이 변경/삭제되면 전송을 중단. 사용자 승인 없이 앱이 스스로 서버에 업로드하지 않음
- 서버 적용 확인이 끝난 뒤에만 첫 대기 요청을 삭제. 폐기는 사용자 별도 승인 필요

## QA

- Android Gradle APK·Lint·API36 에뮬레이터 QA: 완전 격리된 임시 JSON에 저장/읽기/계정 불일치 거부/삭제 검사
- iOS Xcode unsigned IPA + Debug 시뮬레이터 컴파일, Swift 타입 안전성
- Python SQLite SyncStore 기존 멱등 요청·중복 충돌 회귀 테스트, Windows Phase26 테스트
- 3개 플랫폼 정적 계약 점검
- 실제 사용자 토큰·공개 서버를 사용한 플랫폼 E2E는 포함하지 않음

## 명확한 한계

- **실시간 자동 동기화 아님.** 백그라운드 서비스, 자동 토큰 관리, 기존 기록 수정/삭제의 양방향 큐, Android/iOS 실제 서비스 HTTPS 연결, 앱스토어 배포는 미구현/미수행
- 개인 과목·진도·숙제 데이터는 로컬에 포함됨. Android는 앱 내부 사설 파일로 저장하지만 별도 JSON 암호화는 하지 않음; iOS에서는 기기 파일 보호 설정을 적용함. 기기 잠금/백업 필요
- 관리자가 별도 HTTPS OAuth/기기 서버를 준비해야 재전송 가능. 앱 코드만으로 무료 운영 서버가 자동 개설되는 것은 아님
- 중요한 경우 수동 4종 통합 JSON을 안전한 외부 장소에도 보관하고 실기기에서 데이터 복원 검증 필요
- Windows, Android, iOS 앱이 자동으로 동일한 기록을 화면에 표시하는 기능은 아직 완성되지 않았음
