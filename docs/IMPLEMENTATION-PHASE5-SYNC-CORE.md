# StudyOne 개발 5단계 — 로컬 동기화 서버와 Windows opt-in 연결

> 상태: **Canary 연구·개발용 Draft PR**. 앱 자동 동기화 및 새로운 Stable 릴리즈는 아직 아닙니다.

## 실제 구현 및 검증 범위

### 서버: PR #9 기반
- Python 표준 라이브러리/SQLite 로컬 단일 사용자 데이터베이스.
- 127.0.0.1:8765 바인딩만 허용, Bearer 토큰 32자 이상.
- task(기존 일정), progress(교재별 진도)를 나눠 저장하며 원본 앱 백업 JSON 스키마 필드와 일치.
- UUID idempotency, 서버 revision, cursor 기반 append-only 변경 로그 및 삭제 tombstone.
- 같은 ID의 동시 수정 충돌 시 HTTP 409 반환, batch 사전 검증·트랜잭션 원자성.
- 예상치 못한 API key/학교 개인정보 등의 데이터 필드는 거부.
- 유닛·HTTP·보안·충돌 회귀 테스트, 서버 인터넷 배포 없음.

### Windows Canary 연동: PR #10
- Windows 앱의 **동기화 실험** 탭에서 루프백 서버의 현재 기록 건수를 인증 후 조회 가능.
- 사용자 승인 시 **서버에 없는 새로운 ID의 일정·진도만 업로드**. 서버에 이미 있는 ID는 건너뛰며 사용자 데이터나 서버의 기존 기록을 수정/삭제하지 않음.
- 로컬 토큰은 Windows 앱 설정/디스크/JSON에 저장하지 않고 해당 대화 상자에서만 사용.
- 네트워크 자동 재시도/백그라운드 동기화 없음. 일정 또는 진도 UI의 저장 자체가 서버로 보내지는 않음.
- 새 레코드 업로드가 일부만 완료되면, 후속 재시도 전에 서버 snapshot을 다시 읽어 이미 반영된 ID를 걸러냄.
- Windows에서 로컬 서버가 실행 중이고 테스트 토큰이 설정되어 있어야 연결됨.
- 자동 테스트에서 기존 서버 ID를 덮어쓰지 않는다는 규칙 검증.

## 주의

- 서버를 공인 IP나 LAN 0.0.0.0에 바인딩하지 마세요. 로컬 HTTP는 외부 클라우드 동기화용 보안 연결이 아닙니다.
- 기존 모바일·Windows 앱 파일과 v3.0.0-beta.2 및 main 코드는 수정하지 않았습니다.
- 테스트용 로컬 토큰을 공개 대화나 GitHub에 게시하지 마세요.
- 학교/개인 공부 기록 업로드는 명시 동의 후 진행하며, 이 개발 과정에서는 사용자의 실제 파일을 서버에 업로드하지 않았습니다.
- 안전한 정식 배포에는 사용자 데이터 삭제/수정 이력, 검증된 접근 통제, TLS, 엔드투엔드 백업/복구, 모바일 네이티브 클라이언트, 실기기 테스트와 사용성 점검이 필수입니다.
