# StudyOne 10단계 — ChatGPT 읽기·초안 제안·앱 승인 구조

**Canary 프로토타입입니다. 현재 이 ChatGPT 대화와 실제 StudyOne 계정이 연결됐다는 의미가 아닙니다.**

## 보안 설계 목표

ChatGPT가 내 학습 진도와 일정을 읽을 수 있으려면 사용자가 인증된 HTTPS 계정 서버에 장치별 read 토큰을 별도 승인·연결해야 합니다.
AI가 작성하는 공부 계획은 곧바로 활성 일정에 저장하지 않고 **승인 대기 초안**으로만 생성합니다.
사용자 본인이 StudyOne Windows 앱에서 해당 항목을 검토하고, 별도의 read-write 장치 토큰으로 승인할 때에만 새 일정이 반영됩니다.
읽기 전용 Assistant 토큰은 기존 일정의 추가·변경·삭제 직접 실행을 할 수 없습니다.

## 구현된 실제 기능

- 계정별 승인 대기 SQLite 테이블과 최대 20개 미승인 초안, 7일 만료 설정.
- 초안에는 최대 30개의 할 일이 포함 가능. 분류/과목/제목/마감일/중요도 필수.
- 생성 시 서버가 안전한 숫자 ID를 발급하고 신규 항목만 준비. 중복 요청 UUID에 멱등성 적용.
- 계정별 단일 데이터베이스 분리. 다른 사용자의 계획을 조회하거나 승인할 수 없음.
- HTTPS API:
  - GET /v2/proposals — 승인 대기 학습 계획 조회
  - POST /v2/proposals — 초안 제출(read 토큰도 가능, 활성 일정에는 영향 없음)
  - POST /v2/proposals/{UUID}/approve — writable device 토큰 + 확인 후 승인
  - POST /v2/proposals/{UUID}/reject — writable device 토큰 + 확인 후 거부
- 승인 시 기존 동기화 서버의 원자적 일괄 변경 API 호출. 제안 ID를 요청 멱등성 키로 사용하여 재시도로 중복 학습 일정이 생기지 않도록 설계.
- /mcp 경로에서 JSON-RPC 스타일 초기화, 목록, 세 개의 제한된 도구 제공:
  1. studyone_read_snapshot — 사용자 계정에 인증된 일정과 진도 읽기
  2. studyone_pending_study_plans — 승인 대기 목록 읽기
  3. studyone_propose_study_plan — 실제 일정 변경 없는 초안 생성
- Windows Canary 앱에서 대기 계획 목록·세부 문항을 확인하고 사용자가 직접 승인·거부 가능.
- 승인이 완료되면 서버에 일정이 추가됩니다. Windows 로컬 앱에 가져올 때에는 앞서 구현한 **서버의 신규 일정만 가져오기**를 별도로 실행해야 합니다.
- 서버 테스트에서 Assistant read 토큰의 직접 쓰기(403), 다른 계정의 초안 접근 차단(404), 승인 전 스냅샷 불변 등을 확인.

## 이 대화에서 '할꺼'가 앱에 즉시 적용되지 않는 이유

1. 원격 HTTPS StudyOne 계정 서버·도메인·SSL 인증서가 아직 실제 배포되지 않았습니다.
2. 이 ChatGPT 대화의 StudyOne MCP/플러그인 연결과 OAuth 승인 절차가 아직 없습니다.
3. 현재 /mcp는 실험용 JSON-RPC 전송 구현이며, 실서비스용 OAuth 2.1 연결·MCP 호환성 및 보안 감사가 필요합니다.
4. Android/iOS 네이티브 앱의 제안 승인함 UI와 안전한 변경 로그 자동 동기화도 구현하지 않았습니다.

연결되지 않은 상태에서 사용자가 '변경사항 인지해'라고 하더라도 앱 DB를 읽었다고 답해서는 안 됩니다. 데이터가 없는 경우 연결 상태를 명확히 설명해야 합니다.
AI 제안이 승인되었더라도 즉시 다른 기기로 자동 동기화된다는 주장은 금지됩니다.

## 실제 계정 연결 전에 반드시 확인할 것

- 운영용 HTTPS 서비스, 정식 계정 인증/복구, 기기별 토큰 발급/만료/회전 및 유출 대응
- ChatGPT 플러그인/MCP OAuth 인증·권한 동의, 읽기/쓰기 분리, 제3자 접근 통제
- 사용자 기록의 백업/복원·감사·삭제/보존 정책 및 개인정보 처리
- 실제 Android/iOS/Windows의 쌍방향 읽기·쓰기/오프라인 충돌 E2E
- 설치파일 코드 서명과 공식 Stable 릴리즈 수용 테스트

기존 main, 공개 Beta 릴리즈, iOS/Android 서명키, 사용자의 로컬 학습 기록은 변경하지 않았으며 이번 개발 과정에서 개인 API 키나 실사용 학습정보를 외부로 업로드하지 않았습니다.
