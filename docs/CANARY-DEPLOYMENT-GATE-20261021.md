- 실제 ChatGPT 대화↔StudyOne 사용자의 OAuth 인증 연결: 계정별 MCP 스타일 read/propose 도구는 있지만 운영 서버와 연결 승인이 없습니다.
- 실제 사용자 본인 인증·계정 복구, 2FA, 기기 토큰 자동 회전/보관, 운영 환경 rate-limit/침입 방어, 운영 서비스 모니터링 및 보안 심사.
- HTTPS 인증서 발급·갱신, 사용자 데이터를 둘 서비스 제공자 및 지역 선택, 지속 가능한 비용 및 백업 암호화.
- 실제 Android/iOS/Windows 실기기 간 사용자의 승인된 학습 데이터 왕복, 충돌 해결·복원 E2E.
- 교차 플랫폼 UI/UX 일관성 및 성능·접근성 정비, Windows 설치 관리자·코드 서명, iOS 서명·배포/신버전 Stable 릴리즈.

## 다음 사용자 결정이 필요한 이유

연결된 호스팅 서비스에서 Railway에는 기존 프로젝트가 없고, Render는 사용자가 선택해야 하는 워크스페이스가 있습니다. 어떤 서비스에 유료 또는 데이터 저장 리소스를 만들지, 데이터 저장 지역·호스팅 비용을 수락할지는 사용자가 직접 선택해야 합니다.

**단계별 권장 승인 흐름:**

1. 테스트 환경으로 사용할 위치를 고릅니다: Render 워크스페이스 / Railway 개인 워크스페이스 / 본인이 관리하는 분리된 컴퓨터. 기존 마인크래프트 게임 서버 운영 포트·세계 파일과 StudyOne 데이터 서버를 혼합하지 않기를 권장합니다.
2. 개인 공부 기록이 아닌 합성 데이터만 사용할 **격리된 테스트 계정**부터 구성합니다. 서비스 생성으로 비용이 발생할 수 있으므로 먼저 요금·가용 리전을 확인합니다.
3. 유효한 HTTPS 도메인 및 서버 인증서/비밀키 경로를 설정하고 제한된 네트워크 정책을 검증합니다. 원격 HTTP 공개 금지.
4. iOS/Android/Windows 기기 실제 수동 데이터 왕복/삭제 거부/충돌/백업 복원 테스트에 성공한 뒤에만 실제 개인 데이터 이전을 별도 승인합니다.
5. ChatGPT 계정별 OAuth 앱 연결 및 읽기/제안과 실제 승인 권한 분리를 심사합니다.

## 안전 정책

실제 사용자 데이터/학교 정보, 서버 키, 인증 토큰, OpenAI API 키 등 비밀을 GitHub 작업, CI fixture, 대화창에 공개하지 마세요.
현재 복구 도구의 SQLite 백업은 평문이며 저장 디스크 암호화가 필요합니다. 운영 중인 데이터베이스를 자동으로 복구/덮어쓰는 기능은 없습니다.
