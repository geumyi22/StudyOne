# StudyOne 3.1.0-canary.5 — Android 안전한 기기 이전 프리뷰

## 배경
사용자는 3.1.0-canary.3의 7개 실기기 핵심 테스트를 모두 통과했다고 직접 확인했습니다. 설정의 개발자용 로컬 동기화 화면은 PR #31에서 실험임을 분명히 하고 Debug 개발자 항목으로 옮겼습니다.

GitHub Actions의 Android Debug APK는 영구적으로 같은 서명키를 사용한다는 보장이 없습니다. 따라서 같은 패키지 이름으로 만든 새 APK가 기존 앱에 업데이트 설치될 수 있다고 주장하지 않습니다. 이번 새 빌드의 테스트 패키지는 `com.studyone.app.canary5`입니다. 기존 Stable/Beta 및 지난 Canary 앱을 삭제하지 마세요.

## 이번 변경
- Android 플래너 → 관리에서 4종 데이터 **하나의 JSON 파일로 내보내기**:
  1. 기본 학교·학년·반 및 숙제/수행/일정 (NEIS 키 제외)
  2. 교재·시험범위·진도
  3. 일정별 예상 공부 시간·단계·완료 기준
  4. 오답 관리·복습일·숙달 기록
- 각 섹션은 기존 스키마를 JSON 문자열 그대로 보관하므로 기존 개별 JSON 백업/복원도 유지합니다.
- 내보내기 전에 기존 일정을 안전하고 엄격하게 읽고, 가져올 때는 네 개 섹션 모두 스키마·ID·범위 검증, SHA-256 체크섬 확인을 마친 뒤에만 교체 승인 화면을 띄웁니다.
- 가져오기 승인 직전에 현재 네 원본이 변하지 않았는지 재확인하고, 변경 전에 네 원본을 앱 내부 복구용 JSON 하나에 먼저 저장합니다.
- 플래너 → 관리에서 가장 최근 내부 원본 복구 백업 파일을 내보낼 수 있습니다.
- 일반 설정에서 실행 중인 버전이 실제 Android 패키지 정보로 표시되도록 변경했습니다.
- 기존 일정/진도/오답/쓰기 수행 및 7개 플래너 탭, NEIS, 학교/학년/반 등 저장 형식은 유지했습니다.

## 복원 안전성 한계
**중요:** 4종 저장소는 각각 별도 Android 저장소에 있으며 단일 원자적(ACID) 트랜잭션이 아닙니다. 예외 시 일부 섹션만 반영될 수 있으므로 오류 화면을 숨기지 않고 원본 복구 파일을 사용자에게 내보낼 수 있게 합니다. 기존 원본 보관을 성공한 뒤에만 기록 교체를 시작합니다. 복원 전에 앱 데이터를 초기화하지 말고 원본과 내보낸 백업 파일을 보관하세요. 앱 삭제 시 앱 내부 원본 복구 파일도 삭제되므로 별도로 내보내야 합니다.

## 아직 완성하지 않은 기능
- 실제 ChatGPT 연결·계정 로그인, 원격 서버를 이용한 실사용 양방향 동기화, 서명키로 유지되는 안정적 Android 인플레이스 업데이트.
- iOS/Windows에서 통합 4종 백업 파일 직접 가져오기 기능 (각 플랫폼의 기존 개별 JSON 경로를 유지).
- 백업의 자동 클라우드 업로드와 원격 보관, 네 저장소 전부의 원자적 복원.
- Release로 배포할 수 있는 정식 서명은 별도 키·인증/보안 실기기 검증 필요.

테스트 성공과 사용자 실기기 검증은 별도로 관리합니다. `main`과 기존 Beta/Stable Releases는 변경하지 않습니다.
