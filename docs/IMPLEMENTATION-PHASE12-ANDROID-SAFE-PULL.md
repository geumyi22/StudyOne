# StudyOne 개발 12단계 — Android 신규 기록 수동 다운로드 (Canary)

## 실제 구현

- Android 모바일 설정의 동기화 화면에 **서버의 신규 일정만 가져오기**와 **서버의 신규 진도만 가져오기**를 별도 버튼으로 추가했습니다.
- Android의 로컬 일정을 엄격하게 파싱해 원본 JSON이 손상되었다면 다운로드를 차단합니다.
- 서버의 /v2/snapshot(HTTPS 계정 서버) 또는 기존 /v1/snapshot(로컬 개발 서버)을 완전히 검증합니다.
- 기존 로컬 ID는 절대 덮어쓰지 않으며, 같은 ID의 서로 다른 내용을 충돌로 집계하고 건너뜁니다.
- 서버에서만 존재하는 일정/진도의 과목·항목 미리보기, 추가할 건수 및 충돌 수를 표시합니다.
- 사용자가 승인하면 서버 스냅샷과 두 로컬 원본 데이터를 다시 조회합니다. 달라졌으면 중단합니다.
- 승인된 **하나의 분류(일정 또는 진도)만** 병합하고, 병합 전에 해당 분류의 원본 JSON을 앱 전용 보안 파일 영역(Context.MODE_PRIVATE)에 별도 백업합니다.
- SharedPreferences commit()의 저장 결과를 확인하며, 기존 학교/시간표/급식/API 키 설정을 수정하지 않습니다.
- 로컬 학습 기록을 자동으로 삭제하거나 서버의 tombstone을 적용하지 않습니다.
- Android Emulator 순수 합성 데이터 self-test에 새 ID만 추가, 기존 ID 건너뛰기, 충돌 감지, 비정상 서버 payload 거절 시험을 추가했습니다.

## 제한

- **완전한 자동 양방향 동기화가 아닙니다.** 서버에서 기존 ID의 수정 사항 및 삭제 요청은 자동으로 내려받지 않습니다.
- 실제 계정·도메인·TLS 운영 서버 배포는 하지 않았습니다.
- 앱 전용 백업은 원본 사용자 학습 정보가 포함된 평문 JSON이므로 외부 공개·전달 금지. 운영급 암호화/보존 기간/복원 UI가 추가로 필요합니다.
- Android/iOS 로컬 데이터 변경과 서버 기록을 반복적으로 통합하는 오프라인 충돌 엔진은 미구현입니다.
- iOS 수동 새 기록 가져오기 및 백업도 별도 후속 단계에서 구현해야 합니다.
- ChatGPT 실사용 MCP OAuth 연결은 미구현입니다.
- 사용자 개인 공부 기록을 테스트 또는 GitHub에 업로드하지 않았습니다. 실기기 사용자 검증도 아직입니다.

## 결과 확인

GitHub CI: Android build+lint, emulator synthetic self-test, planner and network policy contract. 최신 PR의 테스트 결과를 확인해야 하며 CI 성공이 실기기 사용자 데이터 보존 시험을 대체하지 않습니다.

기존 main, Stable/Beta 릴리즈, 사용자 로컬 기록을 GitHub 작업 중 변경하지 않고 별도 Canary Draft에서 유지합니다.
