# StudyOne ↔ ChatGPT 양방향 연동 설계 (구현 전 초안)

> **현재 미구현.** 아래는 미래 기능의 계약 초안으로, 기존 앱이나 이 대화가 지금 바로 동기화된다는 의미가 아닙니다.

## 1. 기본 원칙

- **StudyOne 데이터 저장소가 권위 있는 원본**이다. ChatGPT의 답변/대화 기억은 최신 앱 DB를 대체하지 않는다.
- 사용자가 앱에서 항목을 수정하면 상태와 수정 시점·버전을 서버에 기록한다.
- ChatGPT의 `할꺼` 요청은 최신 승인된 사용자 데이터 **읽기 → 계획 초안 생성 → 검증 → 사용자 승인 필요 여부 확인 → 앱에 저장 → 저장 결과 조회** 순으로 처리한다.
- `변경사항 인지해` 요청은 마지막으로 확인한 revision 이후의 변경 로그를 읽고 무엇이 바뀌었는지 설명한다. **앱의 수정이 ChatGPT에 무조건 자동 전송/인지되는 것은 아님**.
- 앱의 OpenAI API 호출과 현재 ChatGPT 대화의 플러그인/MCP 연결은 별개의 통합 경로다. 채팅 도구 접근 권한·연결이 실제 제공/활성화되어야 한다.

## 2. 제안 데이터 모델

| 엔터티 | 필수 필드 | 설명 |
| --- | --- | --- |
| `user` | `id`, `created_at` | 인증 대상 사용자; 최소 권한 |
| `subject` | `id`, `user_id`, `name` | 과목 |
| `material` | `id`, `subject_id`, `title`, `source` | 교재·학습지 |
| `exam_scope` | `id`, `exam_id`, `subject_id`, `unit_key` | 시험범위 및 범위 제외 규칙 |
| `progress` | `id`, `material_id`, `unit_key`, `status`, `version` | 완료·진행 중·미완료 등 |
| `category` | `id`, `role_description` | 5개 **고정 분류의 장기 메모** |
| `task` | `id`, `user_id`, `category_id`, `date`, `title`, `detail`, `status`, `version` | 날짜별 공부 및 숙제 |
| `task_event` | `id`, `task_id`, `actor`, `change`, `created_at` | 수정·이월·완료 감사 이력 |
| `sync_cursor` | `user_id`, `client_id`, `revision` | 변경사항 조회 위치 |

- 클라이언트와 서버 시간대는 명시한다. 한국 날짜 기준 계획이 다른 시간대로 잘못 이동하지 않도록 현지 날짜/시간대를 저장한다.
- 아이템 ID는 이름이 바뀌어도 유지하고, `version` 또는 ETag 조건부 갱신을 사용해 오래된 AI 계획이 새 사용자 수정을 덮지 못하게 한다.
- 클라이언트가 오프라인일 때는 안전한 큐를 보관하고, 재연결 시 변경/중복/충돌을 명시적으로 해결한다.
- 기존 로컬 JSON schema 1을 실제 감사한 뒤 손실 없는 이관 경로와 되돌리기 방안을 설계한다.

## 3. 미래 연동 도구 예시 (아직 배포되지 않음)

| 도구(가칭) | 권한 | 목적 |
| --- | --- | --- |
| `studyone.get_snapshot` | 읽기 | 범위·교재·진도·숙제·시험·수행 전체 상태 |
| `studyone.list_changes` | 읽기 | revision 이후 변경사항 |
| `studyone.preview_plan` | 읽기/계산 | 중복·범위 제외·이월 사항 검사와 계획 미리보기 |
| `studyone.save_plan` | 쓰기 | 확인된 계획 생성/변경; 중복 실행 방지 키 필수 |
| `studyone.update_task` | 쓰기 | 조건부 상태 업데이트와 감사 기록 |
| `studyone.get_operation_result` | 읽기 | 쓰기 성공/충돌/실패 결과 조회 |

- 서버는 호출자의 사용자 신원을 검증하고 **인증된 사용자 자신의 데이터에만** 접근할 수 있도록 행 수준/서버 접근제어를 적용한다.
- 읽기·쓰기 권한을 별도 구성한다. 쓰기에서 사용자 승인 정책 및 인증 범위를 지킨다.
- 구조화된 입력 검증, 요청 크기/빈도 제한, 토큰 폐기/만료, 재전송 방지 및 개인 데이터 비노출 로그가 필요하다.
- 실패·충돌 시 성공했다고 답하지 않고 어떤 항목이 저장되지 않았는지 알려야 한다.
- 개인 OpenAI API 키를 현재 앱에서 직접 사용하는 구조는 그대로 복제하지 않는다. 추후 서버형 AI가 필요하면 키/비용/비밀 처리 정책을 별도로 결정한다.

## 4. 동기화 동작 예시

1. 사용자가 StudyOne에서 `과학 오투 7-2`를 완료로 변경한다.
2. 서버가 해당 항목의 버전을 올리고 `task_event`와 revision을 기록한다.
3. 사용자가 ChatGPT에서 `변경사항 인지해`라고 입력한다.
4. 인증된 연결이 변경 로그를 조회하고 정확한 before/after와 기준 revision을 반환한다.
5. 다음 `할꺼` 요청은 방금 조회한 최신 상태를 기반으로 새 계획을 만든다. 완료 항목을 임의로 다시 배정하지 않는다.
6. 새로운 계획을 저장할 때 기반 revision이 바뀌었다면 계획을 자동 덮어쓰지 않고 다시 조회한다.

## 5. 우선 테스트할 실패 사례

- 서로 다른 기기에서 같은 숙제를 동시에 수정
- AI가 예전 `미완료` 상태를 기준으로 이미 완료된 진도를 다시 저장하려는 경우
- 휴대폰 오프라인 수정과 서버 수정이 충돌하는 경우
- 반복된 `할꺼` 호출로 날짜별 과제가 중복 생성되는 경우
- 권한 없는 사용자·토큰 만료·연결 해제·서버 500 오류
- 타임존 경계, 과목/교재 이름 변경, 시험범위 밖 단원 혼입
- 기존 데이터 백업 복원 중 중복·부분 실패·다운그레이드
- AI 도구 응답에 악의적인 텍스트가 있어도 도구 권한 밖 작업을 하지 않는지 검사

## 6. 개발 전 결정해야 할 사항

- 사용자 계정/로그인, 오프라인 사용 범위, 백엔드 호스팅·운영 비용
- Windows 클라이언트 기술과 기존 Android Java/iOS SwiftUI 코드 재사용 전략
- 학습 데이터 보관 기간, 삭제/내보내기, 연령 적합한 개인정보 처리
- ChatGPT 플러그인/MCP 연결의 실제 제공 범위 및 쓰기 허용 여부
- Stable 릴리즈에서 동기화가 필수인지 단계적 출시할지
