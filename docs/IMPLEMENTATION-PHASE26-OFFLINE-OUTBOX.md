# StudyOne Phase 26 — Windows 오프라인 신규 기록 대기열 + 서버 재전송 계약

> 추가 클라우드/외부 유료 서비스 없음. GitHub Canary 소스 기능. 개인 계정 서버, 사용자 데이터, 릴리즈, 서명, 자동 클라우드 동기화는 변경하지 않음.

## 구현 범위

- **Windows 동기화 실험 탭**에 사용자가 명시적으로 선택할 수 있는 `대기열 보관`, `수동 재전송`, `첫 요청 폐기`, `상태 조회` 추가
- 서버가 꺼졌거나 네트워크가 없더라도 새 **일정·진도**의 JSON을 PC 앱 내부 `StudyOneCanary/SyncOutbox/outbox.json`에 저장할 수 있음
- 전송 대상 `계정 UUID + HTTPS 서버 주소`를 대기열에 고정해 잘못된 계정으로 재전송하지 못하도록 함
- **Bearer 토큰/암호/자격증명은 절대 대기열에 저장하지 않음.** 재전송 때 사용자가 토큰 입력, 서버 `GET /v2/session`으로 실제 계정 UUID, `audience=device`, `scope=read-write` 확인
- 각 대기 요청은 고정 **UUID requestId**, 1~50개 신규 기록만 포함. 실패·응답 유실 시 **동일한 requestId**로만 재시도. 서버에서 요청 멱등성을 보장하며 중복 변경을 만들지 않음.
- 실제 전송 전에 반드시 사용자가 승인하고, 로컬 일정·진도의 내용이 대기열 저장 이후 달라지지 않았는지 검사. 로컬 삭제·수정·동기화 충돌·토큰 오류 발생 시 업로드 차단 및 대기열 보존.
- 서버의 기존 ID는 자동 수정·삭제하지 않음. 서버 스냅샷에서 충돌/변경이 있으면 v2의 revision 409 preflight가 **해당 배치 전체 적용을 거부**함
- 서버 전송이 성공하고 응답의 적용 결과를 확인한 뒤에만 대기열 요청을 삭제. 응답을 받았지만 로컬 파일 제거에 실패하면 원본 requestId로 재시도 가능
- 대기열의 로컬 수동 폐기는 **별도 사용자 승인** 필요. 원본 일정/진도는 그대로 보존
- Android/iOS의 기존 데이터 모델·기기 저장/동기화 로직은 바꾸지 않음

## 사용자 워크플로

1. PC 동기화 실험 → 실제 HTTPS 계정 서버 주소와 전송 대상 계정 UUID 입력 (토큰은 아직 필요 없음)
2. 신규 일정·진도를 오프라인 대기열에 보관 → 내용을 확인하고 저장 승인
3. 나중에 네트워크가 가능하면 동일 HTTPS 주소/계정 UUID, 서버에서 발급한 쓰기 권한 토큰 입력
4. 수동 재전송 버튼 → 실제 서버에서 토큰과 계정 ID 인증 후 **첫 번째 대기 요청 1개(최대 50건)** 확인·전송
5. 승인된 요청은 1개씩 처리. 충돌이나 로컬 수정 감지 시 전송하지 않고 기존 대기열을 보존. 상태 버튼으로 개수 확인. 필요하면 별도 승인으로 폐기

## 보안·개발 단계 제한

- PC 대기열 JSON에는 교재·과목·수행평가 등 **개인 학습 기록이 평문으로 포함**됩니다. StudyOne 기존 JSON 저장 정책과 동일하지만 OS 기기 암호화 및 외부 백업이 필요합니다. 학교/공용 PC에서 사용을 권장하지 않습니다.
- 서버 계정 UUID는 오프라인 작성 때 사용자가 입력합니다. 잘못 기입하면 재전송이 차단되며 **자동 계정 감지나 OAuth 로그인 UI를 뜻하지 않습니다**.
- 서버가 이미 가지고 있는 ID는 새 기록인지 판별할 수 없으므로 서버 409 충돌 시 정지하며 자동 덮어쓰기하지 않습니다. 현재 **신규 항목 생성 전용**이며 기존 수정·삭제의 양방향 큐는 아닙니다.
- 자동 백그라운드 재전송·자동 토큰 저장·Windows 서비스·iOS/Android 대기열 UI는 아직 미구현입니다.
- 실제 v2 HTTPS 서버는 운영자가 별도로 안전하게 실행해야 하며 서버 비용/호스팅은 자동 발생하지 않습니다.
- 유저의 실제 과목 진도 64개/65개는 코드 테스트에 입력하지 않았습니다. 모든 QA는 합성 학생 기록을 사용합니다.

## QA 게이트

- Windows .NET portable JSON: 대기열 저장/읽기, 중복 건너뛰기, stable requestId, 오프라인 저장, HTTPS 강제, 잘못된 계정/읽기 권한 차단, 로컬 편집 감지, 위조된 삭제 요청 거부, 성공 ACK 후 제거, 55건의 50+5 배치 분리
- Windows WPF Release 빌드·self-contained EXE CI
- Python SQLite SyncStore: 응답 유실/동일 requestId 재전송, 기존 원격 ID 충돌 시 전체 거부, 요청 ID 재사용 거부, 원격 삭제 tombstone 보호
- 개발용 HTTP/HTTPS 실제 계정·운영 서버 연결은 이 PR에 포함되지 않음. **실기기 운영 서버 E2E와 Android/iOS Queue 구현은 후속 단계**입니다.
