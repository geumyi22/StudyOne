# StudyOne 릴리즈 채널 · 저장소 정리 원칙

> 이 문서는 **향후 운영 원칙**입니다. 현재 공개된 최신 버전 `v3.0.0-beta.2`를 Stable이라고 선언하지 않습니다.

## 1. 채널

| 채널 | 대상 | 승격/배포 원칙 |
| --- | --- | --- |
| Canary | 실험 기능·스키마·플랫폼 검증 | 기능/호환성 변경이 잦으며 별도 식별자/서명/데이터 격리를 검토 |
| Beta | 실제 사용 전 검증 중인 후보 | 자동 빌드/회귀·마이그레이션 테스트, 알려진 문제 공개 |
| Stable | 일상 사용을 권장할 수 있는 정식 버전 | 플랫폼별 릴리즈 수용 기준과 실기기 검증을 모두 통과한 승인 빌드 |

- 릴리즈 채널은 단순 버전 명칭이 아니라 **검증 수준과 사용자 기대치**를 구분한다.
- Canary → Beta → Stable 승격 때는 **동일한 소스/아티팩트 추적성과 검증 기록**을 보존한다. 채널별 앱 설치/데이터 충돌 정책은 구현 전에 확정한다.
- Stable 최초 버전 번호·일정은 지금 정하지 않는다.
- 기존 태그/릴리즈의 asset을 몰래 대체하지 않는다. 실제 새 버전 배포는 별도의 신규 태그와 release note를 사용한다.

## 2. 저장소 구조 관리

- `README.md`: 현재 실제 배포 상태, 지원 기능, 빠른 안내.
- `CHANGELOG.md`: 실제 반영된 변경과 릴리즈 이력. 아직 구현 전 아이디어를 완료 사항으로 적지 않음.
- `version.json`: 현재 앱 빌드/업데이트 정보. **문서 변경만으로 수정하지 않음.**
- `docs/VERSION-MATRIX.md`: 플랫폼별 실제 구현/미구현과 검증 증빙.
- `docs/RELEASE-*.md`: 역사적 릴리즈 근거. 오래됐다는 이유만으로 삭제하지 않음.
- `docs/archive/`: 역사적 워크플로/자료 (실행 대상이 아니라는 점 명시).
- `docs/NEXT-STABLE-ROADMAP.md`, `docs/CHATGPT-SYNC-DESIGN.md`: 미래 계획이며 출시 기능 아님.
- `.github/workflows/`: 실제 CI. 참조·태그·서명·릴리즈 종속성 분석 없이 이름 변경/삭제 금지.

## 3. 변경 관리 체크리스트

- [ ] 현재 `main` SHA, 기존 태그·릴리즈·첨부 파일과 서명 정책 확인
- [ ] 소스/문서/설정 차이를 분리하고 변경 목적을 명시
- [ ] 비밀키·환경 설정·개인 학습 데이터가 커밋되지 않도록 검사
- [ ] Android 빌드·lint·에뮬레이터 회귀(소스 변경 시)
- [ ] iOS 빌드 및 실제 설치·기능 시험(필요 시 별도 기기 검증)
- [ ] Windows 빌드 및 설치형 배포 검증(Windows 도입 후)
- [ ] schema/백업·복구 및 업그레이드 호환성 검증(데이터 형식 변경 시)
- [ ] 출시 파일의 버전명·패키지/번들 ID·서명·SHA-256 일치 검사
- [ ] PR에서 위험/테스트/롤백 경로 검토하고 필요한 승인 확보

## 4. 기존 CI 정리 시 확인할 점 (아직 수정하지 않음)

- `android.yml`의 디버그 artifact 이름 `StudyOne-v2-debug-apk`는 현재 v3 릴리즈 이름과 다름. 업로드/다운로드 양쪽 이름을 함께 바꿀 때만 안전함.
- iOS 워크플로는 특정 경로 변경 시 트리거되며, docs-only 변경은 새 iOS 빌드를 보장하지 않음.
- signed-release 워크플로는 실제 GitHub 릴리즈에 파일을 게시하므로 문서 정리만을 위해 수동 실행하지 않는다.
- 기존 GitHub Actions 실행 기록은 성공·실패의 감사 흔적이므로 대량 삭제하지 않는다.
- 현재 공개된 iOS unsigned IPA와 Android APK는 서로 다른 설치/서명 요구사항을 가진다.

## 5. 롤백

- 문서 변경은 별도 브랜치 및 PR을 우선하며, 문제가 있으면 PR을 병합하지 않거나 병합 커밋을 되돌린다.
- 앱·DB 마이그레이션은 별도 백업과 다운그레이드/복구 설계가 승인되기 전 실행하지 않는다.
